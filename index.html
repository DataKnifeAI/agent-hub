Proposed · plugin layout

            
One folder, every tool

            

              A root plugin.json follows the open
              Agent Plugins standard, which Cursor, VS Code,
              and Copilot load directly. Cursor and Claude manifests sit alongside it for rules and
              Claude-specific pieces. Two marketplace files let every tool install straight from
              this repo.
            

            

              Skills are copied in from agent-skills by CI rather than symlinked, because tools
              reject plugin files that resolve outside the plugin folder. agent-skills stays the
              single source of truth.
            

          

          
agent-hub/
├── .claude-plugin/marketplace.json  # Claude, Copilot CLI, VS Code
├── .cursor-plugin/marketplace.json  # Cursor
└── plugins/
    └── dataknifeai/
        ├── plugin.json               # Agent Plugins 1.0
        ├── .cursor-plugin/plugin.json
        ├── .claude-plugin/plugin.json
        ├── skills/   # copied from agent-skills by CI
        ├── rules/    # conventional commits, small MRs
        └── mcp.json      # templates, secrets via env

Other ways to install

          
The one-liner above wraps scripts/install-skills.sh. These work too.

        

        

          

            
Makefile

            
From a checkout of agent-skills. Symlinks into ./.cursor/skills by default.

            
make install
make install-user
make install ONLY=gh-cli,kubectl-cli

          

          

            
Installer script

            
Point --target at any tool's skills folder. Add --copy for committed installs.

            
./scripts/install-skills.sh --target .claude/skills
./scripts/install-skills.sh --target .github/skills --copy
./scripts/install-skills.sh --dry-run
